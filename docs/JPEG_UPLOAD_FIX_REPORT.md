# JPEG上传结束校验兼容修复

用户实际错误：`IMAGE_INVALID / Invalid JPEG ending`。生产日志此前上传422，存储可写。本轮代码审查发现jpegInfo要求EOI标记紧贴物理文件末尾；完整JPEG主图后有填充、来源数据或相机附加部分时也错误拒绝。

复现：完整、可解码2×3 JPEG追加零填充、来源元数据或容器样式字节，旧校验报相同错误；真实浏览器经上传API同样422。测试先失败再修复。修复仅取消“EOI后不得再有字节”的限制，仍按标记及段长度解析完整主图，要求有效帧、表、扫描及像素内容和结束标记。不会简单寻找第一个FFD9：元数据内伪结束标记不能绕过主图校验。

格式依据：Android官方[Motion Photo格式](https://developer.android.com/media/platform/motion-photo-format)明确照片文件可由静态主图及其后附加视频组成；[libjpeg-turbo解码接口](https://github.com/libjpeg-turbo/libjpeg-turbo/blob/main/doc/libjpeg.txt)以JPEG结束标记结束当前码流。EOI不等于宿主文件必须在此结束。本轮不解析、播放或宣称验证附加视频；仅支持完整主JPEG，全部原字节保留。未读取用户失败原文件，因此只确认该已复现兼容缺陷，与其实际错误一致，不宣称已检查用户原图的所有内容。

上传规则保留：8MiB按整个原文件计算、4000万像素、PNG/JPEG、最多20张、原作业员未锁定可修改、他人历史只读、管理员更正原因、版本检查、审计及私有访问。附加段不作为新文件类型解析，也不会执行。

安全回归：旧“在完整JPEG后加script字符串必定不是图片”的断言改为正确的主图判断；其安全目的改用真实浏览器验证附件始终以image/jpeg、nosniff、私有no-store返回，直接导航也不执行附加脚本；无会话401，他人非历史403。完整原始字节在磁盘及下载响应逐字节相等。截断、无有效帧/扫描、伪EOF、超限和损坏表仍拒绝，PNG附加数据仍拒绝。本轮没有关闭权限或MIME保护。

新增2个单元用例、1个真实浏览器端到端用例。聚焦回归9/9通过，包括实际上传201、浏览器解码2×3、原字节完整、附加文本不执行及权限校验。完整回归与发布证据见下文。
