# Jackery：BOM硬上限、故障知识与紧凑作业页

用户本轮7项授权为当前范围。保留单次检验和单选点；不恢复复测。

## 方案和默认处理

1. 原BOM标准用量作为硬上限，保存/结案/管理员更正同样校验，无管理员超耗例外。相同工单同料一行累计实耗，WFR保存不叠加；新选仍默认1。原表pcs物料按件限制，保留标准量快照。
2. SN扫描器作为键盘输入，录SN后由用户选择型号/版本配置。按modelId加载对应BOM和故障知识，不猜SN对应型号。各版本独立，保留SKU原码。
3. 本地现有作业数据库备份后导入真实目录，保留旧作业/账号；DEMO样例不冒充真实资料，导入后新单使用Jackery目录。新交付包附可重复、幂等的源目录导入能力。
4. 9份BOM逐行保留或说明排除：整机根不计耗、软件不计实物耗用；缺量/型号冲突/争议源状态留待核对、不补数或静默启用。无英文原名不编造，界面明确缺英文并显示原文。
5. 同页故障代码多选、来源原文和常见故障/解决方案面板；按型号隔离。仅选填，未选可保存/结案；存服务器核验的快照，不接受客户端伪造标签。无代码的源温度提示不伪造故障编号。
6. 移除Reference Details可见功能块，历史字段继续保留。布局压缩头部、检验/耗料区域内滚动，次要内容按需展开，固定保存/结果入口；在1366×768及1536×864验证。
7. 英文可见品牌、启动输出和导出文件统一Jackery。原始中文来源、已有账号/历史数据及必要兼容路径不破坏性改写。

## 数据/API合同

- BomItem兼容新增`standardQty:number|null`、`quantityControl:'standard_hard_cap'`、`source`、`reviewReasons`。无源用量时不开启耗料。
- `GET /api/models/:id/knowledge`认证后返回`{faultCodes,repairGuides,notices}`；现有catalog仍返回小型模型定义，知识单独存储，避免整本指南复制进每条modelSnapshot。
- Record新增`faultCodes:string[]`默认空及服务器生成的`faultSnapshot:object[]`。未知/他型号故障码拒绝，既有快照可读；所有更正沿用既有原因/审计/版本规则。
- 数量硬上限由API执行，前端max仅为辅助；返回422/明确limit详情，不截断实耗、不绕过为管理员特例。
- 本地源目录导入按catalogKey幂等，完整事务、来源SHA256/文件/页/行留存；不调用外部翻译或仓库服务。

## 兼容性审查

已知消费者为同包前端和测试。新增知识接口/字段为向后兼容；有标准量的新目录实施更严格数量校验，属于业务已授权的行为变化。移除Reference Details仅改可见布局，旧数据仍保存/导出。现有SQLite/账号不重建、不改变记录归属。
