# BOM 顶部分类标签实施计划

用户已选择视觉方案 1，并授权先修改系统布局，分类 BOM 待用户提供后再导入。本计划按该确认实施，无需再次确认。

## 边界与设计

- 在现有 BOM 抽屉搜索框下增加 All Items / 全部、Core / 核心、Non-core / 非核心、Packaging / 包材四个标签；默认全部。右侧待选清单及数量输入保持。
- 每个标签显示当前型号可领用物料总数（不随搜索关键词变化）。搜索与类别组合过滤，换类别或查询回到第一页。分类入口固定，物料表格内部滚动。
- 现有无分类或无法识别的记录仅归入全部，显示待补充分类的数量；不猜测类别，不修改原始 JSON、BOM 数量、启用/挂起标记或资料。
- 为分页正确性，现有 GET /api/models/:id/bom 增加可选 category=all|core|non_core|packaging，默认 all；原分页/排序/权限保留。返回 categoryCounts 作为附加字段，unknown/missing 计入 uncategorized。属于向后兼容扩展，无数据库迁移、导入或写接口变化。
- category 字段只读消费。正式分类字段如何从新版 Excel 映射，在用户提供文件后处理；本次不扩展任何导入入口。
- 类别、搜索、分页、语言切换均保留已选项及数量；上限、去重、锁定、型号隔离沿用原规则。语言按账号切换，不强制在标签内同时显示两套文字；物料描述继续英文在上、中文在下。

## 预期改动

server.js 只读分类过滤与总数；public/app.js 分类标签及保留状态；public/styles.css 抽屉布局；tests/bom-category-fixture.js 仅隔离测试数据；tests/bom-categories.test.js 和 tests/bom-categories.test.mjs 回归；规则和发布证据文档。不改 catalogs、数据库文件、用户源表或依赖。
