# v0.3 深度闭环测试计划（2026-10-30）

## 基线

- 唯一业务判定基线：docs/reference/英文界面与现表字段映射_方案v0.3.md，配套 v0.1/v0.2。用户本轮明确恢复 ROK 完工复测全部 Pass，替代此前单次检验修正；原历史文档与提交不改写。
- EN2 BOM 抽屉＋三栏互斥结果。仅记录物料耗用，无库存、入库、审批、自动翻译、迁移或外部接口。
- 测试顺序：主链路→双语→BOM/SKU→权限状态→照片导出及映射。
- 修复必须先失败复现、再定位到界面／状态／API／存储／导出边界，修复后专项＋此前通过功能全量回归。连续五次同因修复失败则暂停告警。

## 预置数据

全部在 tests/.tmp 独立 SQLite 库中生成。admin、alex、blair 使用项目既有 DEMO 测试身份，不接触真实账号；两种 Sample 型号，其中型号 A 有 820 条样例 BOM（含包材），检查 AC Output/DC Output/Charging。

新增样例：DEEP-V03-xxx 独立/重复 SN；两个作业员的相同 SN 历史；WFR 多次保存；含全部映射字段的中文历史；中英混合备注、手工译文；空 BOM 型号；缺英文的旧 BOM；长英文名与特殊 SKU；有效 PNG、伪造 PNG、SVG、超 8 MiB 文件；最终 Fail/Not Tested/Pass 三种复测。

## 待澄清（不擅自形成新业务规则）

1. 用户清单写抽屉“不遮挡”，v0.2/v0.3 明确抽屉会暂遮部分表单。本轮以 v0.3 为唯一判定：同页保留、不丢输入、关闭可返回；不另做新布局。
2. v0.3 对旧 SKU、栈板、校验、父记录、文本9的业务含义仍写待核对。本轮依用户明确指令提供原值参考展示和存储/导出，不编造生成、校验、审批或关联工单逻辑。
3. 正式型号、功能清单、真实最大 BOM、英文业务名称和原始飞书全量数据尚未提供；测试只覆盖可构造样例和已归档字段映射，不声称审计过真实飞书全部记录。
4. v0.2 重复物料规则优先于 v0.1 早期“累计”建议：提示并定位已有行，由作业员明确更改数量，不静默累加。

## API 合同核对

- 已知消费者：同包 public 前端、API/浏览器测试；未发现外部消费者。
- 检查恢复 initial/final，ROK 复测门禁属 POTENTIALLY BREAKING 行为修复；新旧记录未提供 final 时为 Not Tested，禁止编造 Pass。
- 原文/手工译文和旧表参考字段为 BACKWARD COMPATIBLE 可选字符串扩展，缺省为空，无自动翻译。
- 用户 language 为可选响应字段，默认 en；新账号偏好接口依赖既有会话与 CSRF。SQLite 幂等增加一列，保留既有记录。
- 导出 language=en|zh 只切换表头，不改历史值；缺省 en，四张工作表名称保持稳定。
